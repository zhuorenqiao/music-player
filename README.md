# 流光音乐 · Light Music Player

一个现代本地音乐播放器：React 18 + Vite + TypeScript，界面层是组件，播放/列表/解析层是纯模块。没有 UI 组件库、没有 CDN 外链，样式是一整套手写 CSS 变量主题。

---

## 快速开始

```bash
npm install          # 装依赖
npm run dev          # http://127.0.0.1:5173
npm run build        # tsc -b && vite build → dist/
npm run typecheck    # 只做类型检查
node tests/t-tags.mjs  # 内嵌标签解析的字节级用例（42 条断言）
```

`npm run dev` **一个进程就够**：三个同源代理已经做成 Vite 中间件（`src/server/music-api.ts`），不再需要单独的后端脚本。

1. **HTTP Range** 由 Vite 静态服务提供，拖动进度条到未缓冲位置能正常续播。
2. **`/api/lyrics` 歌词代理**。服务端并行查 LRCLIB 多路条件（见「歌词」一节）并缓存到 `.cache/lyrics/`，绕开浏览器 CORS 与系统代理。**没有这个端点时（纯静态部署）前端会自动回退到浏览器直连公共 API**，功能不受影响，只是慢一些。
3. **`/api/cover` 与 `/api/cover/img` 封面代理**。按歌手 + 歌名查 iTunes，命中后把图片下载到 `.cache/covers/img/`，前端拿同源地址当封面 —— 一次性绕开防盗链、混合内容与系统代理三类问题。
4. **`/api/artist-image` 歌手写真图代理**。专辑封面没匹配上时，按歌手名去维基百科取条目配图（zh 优先、en 兜底），图片落盘在 `.cache/artists/`。

> **上游延迟要有心理准备**：LRCLIB 单程实测 15~30s 且偶发 503，iTunes 约 0.4s，而 wikipedia.org 在部分网络下直接被 DNS 污染到不可达。所以歌词代理是**并行多路 + 有限超时**，歌手写真图是 8s 就放弃并落到本地生成封面卡 —— 慢源不会拖住界面。

> `npm run build` 出来的 `dist/` 是纯静态站点，**没有中间件**：前端会自动降级（歌词直连 LRCLIB、写真直连维基 REST），但 iTunes 不开 CORS，所以封面匹配会退化。要完整功能请用 dev server 或把中间件挂到自己的 Node 服务上。

> 依赖源：`registry.npmjs.org` 在部分网络不可达，仓库里带了 `.npmrc` 指向 npmmirror；换网络后删掉那行即可回官方源。

## 功能

### 播放控制

- **播放 / 暂停**：主按钮切换，图标联动；播放中封面**整圈缓慢顺时针旋转**（默认 24s 一圈，改 `--cover-spin-duration` 一个值即可），外圈光晕呼吸；**暂停时不摘动画、只冻住 `animation-play-state`** —— 封面停在当前角度，恢复播放接着转，不会跳回 0deg。歌词页头部的小封面同步，切页时角度会交接（`handOverCoverSpin`），来回切也看不到跳变。`prefers-reduced-motion` 下整段旋转关闭。
- **上一首 / 下一首**：当前曲目已播放 **超过 3 秒** 时，「上一首」回到本曲开头；否则切到上一曲（标准行为）。
- **进度控制**：
  - 支持点击跳转与拖拽（触摸设备同样可用）；
  - 显示 `当前时间 / 总时长`（`mm:ss`），时长未知时显示 `--:--`；
  - 拖拽期间暂停 `timeupdate` 同步，松手后 seek，不会被播放进度打断；
  - 进度条下方显示已缓冲（buffered）区间。
- **音量**：0–100 滑块 + 一键静音/恢复；静音会记住静音前的音量；图标随档位变化；设置持久化。

### 播放列表

- 列表项显示封面缩略图、曲名、歌手、时长；当前项高亮并带跳动音柱指示。
- 点击任意项立即播放。
- 删除单曲（删除当前播放项时自动切到下一首；列表清空则停止并展示空状态）。
- 添加本地音频：点击「添加音乐」多选，或把文件**整页拖放**进来；使用 `URL.createObjectURL` 播放，移除/清空时 `URL.revokeObjectURL` 释放内存。
- 一键清空播放列表。
- **刷新不丢**：本地音频的 Blob 会写进 IndexedDB，刷新后重新生成 `blob:` 地址还原歌单（含顺序、当前曲目、封面、时长与已匹配的歌词）。
- **曲名与歌手从哪来**：优先读文件**内嵌标签**（ID3 / Vorbis Comment / MP4 ilst 的 title、artist、albumArtist、album），没有标签才退回文件名 —— 形如「歌手 - 歌名」或「歌名 - 歌手」都会拆开，拆错了也会被标签纠正（纠正结果同样落库，下次启动不再重复解析）。

### 封面（自动分析 + 四级兜底）

**不需要手动准备封面**：导入本地音乐后，播放器按下面的顺序一路往下找，直到出现一张属于这首歌的图：

1. **文件内嵌封面**（最准，零网络）：`audio-tags.js` 直接解析音频字节 —— ID3v2.2/2.3/2.4 的 `APIC`（含整标签/单帧 unsynchronisation、UTF-16 文本、mime 缺失时按魔数嗅探）、FLAC 的 `PICTURE` 块、OGG 的 base64 `METADATA_BLOCK_PICTURE`、M4A/MP4 的 `moov.udta.meta.ilst` 里的 `covr`。取到后缩放成 ≤600px 的 JPEG data URL，随曲目写进 IndexedDB，刷新仍在。
2. **iTunes 专辑图**：按「歌手 + 歌名」查 iTunes Search（免密钥、官方图）。歌名完全一致或歌手对得上才采用，得分不足宁可继续往下走 —— 避免「光年之外」这类原版只有外文名的歌错配到翻唱 Live 版；中国区与美区商店都查一遍，全局取得分最高的一条。
3. **歌手写真图**：`artist-image.js` 按歌手名取维基百科条目配图（zh 优先、en 兜底）。走本地服务 `api/artist-image`（服务端下图并落盘，前端拿同源地址），纯静态部署时降级浏览器直连维基 REST（该接口带 CORS）。
4. **本地生成歌手封面卡**：`generated-cover.js` 从歌手名派生一张 SVG —— 配色与声波柱形状来自 FNV-1a 哈希，中间是首字（CJK 取一个字、拉丁取两个首字母），下方写歌手名与曲名。**内容全部落在「安全圆」内**（界面把封面裁成正圆，贴边贴底的像素会被剪掉），完全离线、同一歌手恒定结果，所以冷门歌手也不会只剩一张跟这首歌无关的音符图。

- **生成卡不写回 `track.cover`**：那个字段一有值就代表「已经有真封面」，会让后续的在线匹配永久跳过；生成卡只活在显示层（`coverForDisplay()`），写真图或专辑图一旦到位就自动替换掉它。
- **两级通道**：本地服务代理（服务端搜索 + 下载图片落盘，前端拿同源地址，绕开防盗链 / 混合内容 / 系统代理）；没有本地服务时自动降级 JSONP 直连 iTunes。
- **缓存**：结果（含「没找到」）写 localStorage（命中 30 天、未命中 3 天），服务端图片与元数据各缓存 30 天，同一首歌第二次是毫秒级。
- **触发时机**：切到没有封面的曲目时自动匹配；添加本地音乐后还会后台预取前 3 首，切过去时封面已经就位。
- **持久化**：匹配结果随歌单写进 IndexedDB / localStorage，刷新后无需重新联网。
- **优雅降级**：任何一级失败都静默往下走，永不阻塞播放、不打扰用户。

### 歌词（自动匹配）
**不需要手动准备歌词文件**：播放任意一首歌，播放器会按「曲名 + 歌手 + 时长」自动去歌词库匹配。

- **展示位置**：歌词常驻在封面卡内、曲名与歌手下方，是一个约 3 行的同步预览块（当前行高亮、上下行淡出，隐藏滚动条）。右侧面板不再单独设「歌词」类目，只有「播放列表 / 最近」。
- **完整歌词页**：点击曲目区任意位置（歌名、歌手、留白都算；**封面除外——点它是放大看大图**；歌词行也除外——点它是定位播放）**在页面内直接切换**到完整歌词页——不是弹窗，曲目区与列表面板让位；正文是**左右两栏：左歌词、右封面大图**（封面在这一页不旋转，但**点它同样能放大**，滚轮缩放 + 拖拽平移与曲目区封面共用一个放大层）；封面下方是**律动频谱条**：竖直频谱柱 + 横向彩虹渐变 + 柱顶峰值点阵，按曲目 id 确定性生成（每首歌形状不同）；播放段会发光、柱高轻微起伏、峰值点带衰减拖尾，未播放段压暗但仍可读，暂停冻结；`prefers-reduced-motion` 下静态显示，纯装饰、对读屏隐藏，歌词大字号、当前行自动居中、可滚动，**播放控制条仍留在页面下方**，播放/暂停、进度、音量不用退出就能操作。返回方式两种：左上角「返回」按钮、按 `Esc`；返回后焦点还给原处。歌词页里点任意一行也能跳转。
- **控制条小圆碟**：`.controls` 最左侧多了一张 46px 的圆形封面，取的就是当前曲目那张图，跟主封面同速转、同步停。它在两个视图里都常驻可见，所以做成**开关**：在播放界面点它进完整歌词页，停在歌词页时点它回来；`aria-label` 跟着状态在「打开完整歌词页 / 返回播放界面」之间切换。三张碟（主封面、歌词页头部、控制条）在每次切视图时会对齐到同一个角度，不会各转各的。
- **封面放大层**：点封面（或键盘 `Tab` 到封面后 `回车`）弹出全屏遮罩，看的是**完整方图** —— 曲目区里封面被裁成圆碟、四角看不到，这里补回来。关闭方式三种：点图以外的任意遮罩、右上角关闭按钮、按 `Esc`；点在图上不关闭。**滚轮缩放（1×～4×，以光标为锚点）、放大后可按住拖拽平移**；位移会被夹在「图片边缘不离开视口」的范围内，缩回 1× 时自动回到正中，关闭或换歌也会复位。层开着时 `Tab` 不会漏到背后的页面，其它快捷键（空格切播放、方向键快进等）也全部让位，关闭后焦点还给封面。放大用的是当前已经拿到的那一张（内嵌封面 / iTunes 专辑图 / 歌手写真 / 本地生成卡），不会为大图再去找更高分辨率的源。

- **数据源**：[LRCLIB](https://lrclib.net)（开放、免密钥、返回标准 LRC）。
- **匹配顺序**：本地服务把「带时长精确 / 不带时长精确 / 宽松搜索」**并行**发给 LRCLIB，谁先给出可信结果就用谁。精确命中优先返回，搜索命中兜底 —— 上游单程实测 15~30s，串行三级最坏要一两分钟，前端只会误判成「功能坏了」。
- **歌手与歌名对调重试**：文件名既可能是「歌手 - 歌名」也可能是「歌名 - 歌手」，一旦拆反，查询参数就是反的、永远查不到（这正是「一直提示服务维护」的真实原因）。代理会用对调后的组合再查一遍，命中后把结果**同时写到两个 key 下**，下次无论哪种写法都瞬时命中。
- **抗抖动**（歌词库是社区维护的公共服务，会间歇性 503 / 握手超时）：
  - 5xx 与网络错误自动退避重试一次（遵循 `Retry-After`），404 不浪费请求；
  - 连续失败后进入 60 秒**冷却**，期间不再自动打接口，并提示「25 秒后自动重试」，到点自动补一次；
  - 本地服务代理会对上游失败回退到**过期缓存**，宁可给旧歌词也不让界面空着；
  - **失败原因分得清**：代理把上游失败归一成 `rate-limit` / `timeout` / `unreachable` / `upstream` 四类并带上中文说明，界面按类给话术 —— 超时就说超时，不再一律写成「服务在维护」；
  - 时间预算对齐：服务端总预算 45s（`LYRICS_DEADLINE`），前端 `TIMEOUT_PROXY` 60s，保证前端不会比后端先放弃；
  - 所有成功结果双层缓存（localStorage 30 天 + 服务端磁盘 30 天），同一首歌第二次是毫秒级。
- **格式兼容**：支持标准 LRC、一行多时间标签、`[offset:]`，以及**逐字增强型 LRC**（`[00:12.00]<00:12.000>青<00:12.300>花` 这类行内标签会被剥离）；自动剔除开头的「词：方文山 / 曲：周杰伦」等署名行与「歌名 - 歌手」标题行（只在开头 4 行内判断，且至少保留 3 行正文）。
- **同步高亮**：按 `timeupdate` 推进，当前行高亮、唱过的行淡出；二分查找 + 0.12s 容差，不会在行边界反复跳。
- **自动居中**：当前行滚到可视区中央，上下边缘渐隐；手动滚动时暂停跟随 2.6s。
- **滚动条只在滚动时出现**：歌词、播放列表、最近播放三个滚动容器平时滑块透明，滚动时浮现、停手 900ms 后收回（`useAutoHideScroll`）；容器始终保留 8px 槽位，出现/消失不会让内容横向跳动。
- **点击跳转**：点任意一行跳到该句时间点。
- **纯文本降级**：歌词库只有原文没有时间轴时，静态展示全文（不高亮、不响应点击），并在状态行注明。
- **缓存**：结果写进 localStorage（命中 30 天、未命中 3 天），配合本地服务的磁盘缓存，同一首歌第二次是毫秒级；**添加多首本地音乐时还会在后台预取**，切歌时基本不用等。
- **状态可见**：匹配中显示转圈与「首次查询较慢」提示；成功后标注来源；未收录时显示「未找到 + 重试」；网络异常时显示具体原因并可重试，**永不阻塞播放**。
- **手动兜底**：仍支持把 `.lrc` 文件拖进页面（或「添加音乐」选择），支持**批量导入**。匹配规则按可信度取最高分：「歌手 - 歌名」组合名一致 > lrc 名拆出歌名且歌手一致 > 曲名与 lrc 文件名一致 > 仅歌名一致；音频文件名带歌手被拆分显示时也能正确配对。批量导入时对不上名的歌词会跳过并提示（不会全部堆到正在播放的歌上）；单个导入对不上名时挂到当前曲目。手动指定的歌词优先级最高，联网匹配结果不会覆盖它。
- **隐私**：只把曲名/歌手/时长发给歌词服务，不上传音频文件本身。

> 歌词匹配需要联网。离线时已缓存的歌曲仍能显示歌词，未缓存则会提示「离线」。

### 最近播放

右侧面板第三个标签（`最近`）保留最近播放过的 50 首，按时间倒序。

- **自动记录**：真正开始出声时才记（被浏览器拦下的自动播放不计入），记录曲名/歌手/封面/时长/时间戳。
- **重播置顶**：再听同一首歌会把它挪到最前，**永不产生重复条目**；同一首歌 500ms 内的重复事件直接忽略，避免暂停/恢复刷屏。
- **相对时间**：`刚刚` / `N 分钟前` / `N 小时前` / `昨天` / `N 天前` / 一周以上显示日期（跨年带年份）。
- **点击即播**：点任意一条切到那首歌；当前播放项高亮。
- **失效标记**：曲目被移出播放列表后，历史条目会变暗并标注「已不在列表」，点击给出提示而不是静默失败。
- **清空**：一键清空历史（空态时按钮自动禁用）。
- **持久化**：历史存在 localStorage，刷新后仍在，与歌词/歌单互不影响。

### 播放模式

| 模式 | 行为 |
| --- | --- |
| 列表循环 `list` | 播放结束按列表顺序切下一首，末尾回到第一首 |
| 单曲循环 `one` | 播放结束原地重播（手动点「下一首」仍然会切歌） |
| 随机播放 `shuffle` | 洗牌队列，一轮内不重复；一轮结束重新洗牌 |

模式按钮点击循环切换，图标与无障碍文案同步，并持久化到 localStorage。

### 快捷键

| 按键 | 功能 |
| --- | --- |
| `空格` | 播放 / 暂停（不会滚动页面） |
| `←` / `→` | 快退 / 快进 5 秒 |
| `↑` / `↓` | 音量 +5% / -5% |
| `M` | 静音 / 取消静音 |

输入框（文本输入、文本域、下拉框）聚焦时不触发快捷键；滑块聚焦时方向键交给浏览器原生处理，避免双倍响应。

### 响应式

- **桌面（≥900px）**：左右双栏 —— 左列是封面 + 曲目信息 + 歌词预览 + 控制区，右侧是「播放列表 / 最近」标签面板（内部滚动）；左列纵向撑满可用高度，控制区底边与右栏面板底边对齐。
- **移动端（<900px）**：单栏堆叠（曲目信息 → 标签面板 → 控制区），控制区 `position: sticky` 真正吸附在视口底部，滚动列表时不会滑走，列表最后一项也不会被遮挡；触控目标 ≥44px。
- **移动端**：封面 + 歌词预览 + 面板单栏堆叠；完整歌词页同样按一屏布局（头部封面隐藏、字号略降一档），控制条仍吸附在底部。
- 全站无横向滚动条，长曲名/歌手名统一 ellipsis 截断。
- 暂停时列表音柱保持静止（无动画），播放时才起舞。

### 无障碍

- 所有按钮都有 `aria-label`，两个滑块都有 `aria-valuetext`，焦点环可见；
- 桌面双栏的视觉顺序与控制区 DOM 顺序不一致，因此页面第一个可聚焦元素是「跳到播放控制」的 skip-link，按 Tab 即显形，回车直接落到播放按钮；
- `prefers-reduced-motion: reduce` 时关闭所有装饰动画；
- Toast 容器带 `aria-live="polite"`，同屏最多 1 条、其余排队，既不遮挡内容也不丢消息。

## 异常处理

| 场景 | 处理方式 |
| --- | --- |
| `MEDIA_ERR_ABORTED (1)` | Toast：「音频加载被中断，请重试」 |
| `MEDIA_ERR_NETWORK (2)` | Toast：「网络错误，无法获取音频文件」 |
| `MEDIA_ERR_DECODE (3)` | Toast：「音频解码失败，文件可能已损坏」 |
| `MEDIA_ERR_SRC_NOT_SUPPORTED (4)` | Toast：「格式不支持或音频文件不存在」 |
| 曲目加载失败 | 该曲目在列表中打上「损坏」角标 → 延迟 1.4s 自动跳下一首 |
| 全列表都失败 | 连续失败次数 ≥ 列表长度时**熔断**：停止自动跳转、暂停播放，列表上方显示常驻提示 + Toast，不会无限跳转 |
| 不支持的文件格式 | 添加时按 MIME + 扩展名白名单（mp3/wav/ogg/oga/opus/m4a/aac/flac/webm/weba/mp4）预校验，不支持的明确提示并跳过 |
| `play()` 被拒绝 | 捕获 `NotAllowedError`（自动播放策略）等异常：弹出提示 + 在播放列表上方给出常驻提示条和「继续播放」按钮；用户在本页任意一次真实交互（点击/按键）后自动重试，最多 3 次，绝不无限重试 |
| 本地文件时长未知 | 加入列表后用临时 `Audio` 预读 `loadedmetadata` 回填时长；3 秒超时则保持 `--:--`，不阻塞入列流程 |
| 歌词文件无时间轴 | 解析不出任何 `[mm:ss]` 行时拒绝导入并提示，不会把已有歌词冲掉 |
| 歌词匹配失败 | 状态行显示具体原因（超时 / 限流 / 解析失败）+「重试」按钮；限流时 25 秒后自动再试一次；不阻塞播放 |
| 歌词库未收录 | 显示「未找到《曲名》的歌词」+ 重试，空状态里提示可手动拖入 `.lrc` |
| 离线 | 直接跳过网络匹配并提示，已缓存的歌词照常显示 |
| 本地存储不可用 | 隐私模式或浏览器不支持 IndexedDB 时提示「刷新后需要重新添加」，当前播放不受影响 |
| 存储配额不足 | 捕获 `QuotaExceededError` 并明确提示，不会静默丢数据 |
| localStorage 异常 | 读写全程 `try/catch`；数据损坏时回退默认值并清理脏数据，绝不白屏 |
| 加载中 | 播放按钮显示 spinner、封面显示骨架微光 |
| 空列表 | 展示空状态引导文案 |

**如何手动验证异常处理**：把 `public/assets/audio/track-01.wav` 临时改名（或删掉），刷新页面后点击播放，即可看到错误提示 + 「损坏」角标 + 自动跳到下一首；三首都改坏则触发熔断提示。

## 技术说明

- **模块职责**：`lib/playlist.js` 只管数据与顺序，`lib/player.js` 只管音频与错误分类，`lib/lyrics.js` 只管 LRC 解析，`App.tsx` + `state/*` 是唯一的界面与编排层，`lib/storage.js` 只做带容错的持久化。彼此互不越界。
- **进度值走 `useSyncExternalStore`**：`timeupdate` 一秒约 4 次，塞进 Context 会让整棵树跟着重渲染；`usePlaybackTime()` / `useBufferedEnd()` 只通知订阅了进度的组件（进度条、时间文字）。
- **context 的 value 必须换身份**：React 只在 context **值变化**时才通知消费者。`refresh()` 只递增 version，若 value 的 memo 依赖里没有 `version`（或 `Playlist.tracks` getter 返回同一个数组引用），界面就不会重画 —— 表现为「歌词挂上了、封面到了、时长填了，但屏幕不动」。
- **元数据与图源三兄弟**：`audio-tags.js`（纯字节解析，不联网、不碰 DOM）、`artist-image.js` 与 `generated-cover.js`（一个只管取图缓存，一个纯字符串拼 SVG）。汇合点在 `state/covers.tsx` 的 `coverForDisplay()`。
- **内嵌标签解析的边界**：只读需要的那段字节（头部 64KB 判格式，标签区按需再读，上限 8MB），任何一段解析失败都只影响对应字段 —— 畸形长度、越界帧、无 `moov` 的 MP4 都不许抛出去。字节级用例见 `tests/t-tags.mjs`（`node tests/t-tags.mjs`，覆盖 ID3v2.3 / v2.4 unsync / ID3v1 / FLAC / OGG / M4A 与畸形输入）。
- **`Playlist.addMany` 会克隆曲目对象**：所以「按 id 传进来的 track 对象」可能不是列表里的活对象。批量回填元数据（标签、时长、封面）必须先用 `playlist.tracks.find(t => t.id === id)` 找回活对象再改，否则数据落库了、界面还是旧的。
- **歌词自动匹配**：`lyrics-source.js` 负责把曲目归一化成查询（拆歌手/歌名、去噪声标记、带时长），服务端并行跑多路并按相似度挑选，结果写 localStorage 缓存；状态层只负责把结果渲染到界面。切歌时用请求序号 + `AbortController` 丢弃过期响应；列表里没歌词的曲目会后台顺序预取（限速 350ms），当前曲目走带状态的正常流程。
- **手动歌词优先**：`.lrc` 按文件名可信度配对（50「歌手 - 歌名」组合名 > 45 拆出歌名且歌手一致 > 40 曲名一致 > 30 仅拆出歌名），挂上后 `lyricsSource='manual'` 并写进 IndexedDB，自动匹配不会覆盖它。
- **歌词容器的高度是确定值**（桌面 `flex:1 + height:0`，移动端固定 `min(40vh,330px)`），居中用的内边距由高度算出；若高度随内容变化，就会形成「内边距 → 撑高 → 内边距」的自激循环。
- **跳转守卫**：给 `currentTime` 赋值本身会再次派发 `playing` 事件，所以「记忆目标位置 → 在 `playing` 里纠偏」必须限制为**一次记忆最多补做一次**，否则 `赋值 → playing → 再赋值` 会自激成死循环，播放位置永远停在起点。
- **随机播放**：维护一份索引洗牌队列（`#shuffleQueue`）与游标（`#shufflePos`），切歌时按队列推进，因此一轮内绝不会重复；用户手动点选某首歌时游标会同步到队列中的对应位置，之后继续沿队列推进；列表变化时重建队列。
- **失败熔断**：`consecutiveFailures` 只在真正可以播放（`canplay`/`playing`）时清零，因此坏文件再多也只会走完一圈就停下。
- **持久化范围**：
  - localStorage：音量、静音、播放模式、当前曲目、内置/远端曲目的元数据、**完整播放顺序**、**最近播放历史（50 条）**；
  - IndexedDB（`local-store.js`）：用户添加的**本地音频文件本身**（Blob）及其封面/时长/歌词。
  - 因此**刷新后歌单（含本地音乐）会原样恢复**，并自动停在上次播放的那首（不自动播放，遵循自动播放策略）。删除单曲 / 清空列表会同步清理 IndexedDB 记录。
  - 注意：IndexedDB 按**源**隔离，`http://127.0.0.1:5173` 与 `http://localhost:5173` 属于两个源，请固定用同一个地址打开。浏览器配额不足或处于隐私模式时会提示「刷新后需要重新添加」，不影响当前播放。
- **兼容性**：面向现代浏览器（Chrome / Edge / Safari / Firefox 较新版本）。用到了私有类字段（`#field`）、可选链 `?.`、空值合并 `??`、`Array.prototype.includes`、`toggleAttribute`、`backdrop-filter` 等特性。
